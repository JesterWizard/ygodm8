# Session Log — 2026-07-08

## Save-load migration fix for new custom cards

**Worked on:**
- Root-caused missing trunk cards on existing saves: `g20245AC`/`sub_80588C4` used `NUM_CUSTOM_CARDS` as the save-block size, so adding cards changed the save layout — old saves read past trunk qty into adjacent shop qty fields, corrupting the new card slots.

**Fix:**
- Changed save/load size from `NUM_CUSTOM_CARDS` (variable, grows when cards are added) to `CUSTOM_CARD_QTY_BYTES` (fixed at 0x200 = 512) in:
  - `card_hooks.c` — `sub_803519C__Replacement` (load path)
  - `code_800AC64_hooks.c` — `sub_800AD84__Replacement` (save path)
- `SanitizeCustomCardQtyBuffers` already zeros padding indices 339–511 before saving, so the extra bytes are always clean.

**Files touched:**
- `src_custom/card_hooks.c` — load size: `NUM_CUSTOM_CARDS` → `CUSTOM_CARD_QTY_BYTES`
- `src_custom/code_800AC64_hooks.c` — save size: `NUM_CUSTOM_CARDS` → `CUSTOM_CARD_QTY_BYTES`

**Note on existing saves:** The 10 new cards will show in the trunk menu (since `hide_unowned_trunk_cards = FALSE` and the trunk list includes all custom card IDs), but will have quantity **0** on old save files — there's no migration of qty values from the old save boundary. Starting a new game sets all custom cards to 3 copies.
