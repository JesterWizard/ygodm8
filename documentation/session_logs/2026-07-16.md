# Session Log — 2026-07-16

## Fixed: synchro frame palette overwritten by extended art palette

**Root cause:** The call order in `print_card.c` is `sub_80267E0()` then `CopyCardArtDataToBuffers()`.  
1. `sub_80267E0__Replacement` writes the synchro frame palette (40 bytes) to `gUnk_8E01368 + 0x40` (GBA palette bank 4, entries 64+).  
2. `CopyCardArtDataToBuffers__Replacement` then copies the card art palette (128 or **224** bytes for extended palette cards) to `gUnk_8E01368` starting at entry 0. With 224 bytes = 112 entries, it overwrites entries 64-111 (banks 4-6), destroying the frame palette. The art palette data at bank 4 is random frame-garbage, causing "splotches of black all over."

**Fix:** At the end of `CopyCardArtDataToBuffers__Replacement`, re-apply the frame palette (40 bytes to `gUnk_8E01368 + 0x40`) using `GetCustomCardColorPalette()` for new colors or `gUnk_8E137C4[]` for vanilla colors — same logic as `sub_80267E0__Replacement`.

## Fixed: EWRAM u16 alignment (18 stale pads removed, 12 correct pads inserted)

**Root cause:** The ram_map_ewram.s bump allocator simulation (`ram_map_layout.py`) checks that size-2 (u16) allocations land on even addresses using a pure-bump simulation. Over time, upstream additions of 1-byte allocations shifted parity so that 15 alignment pads (`*Pad`, size 1, added via ponytail comments) were actually at the wrong positions — they made parity *worse* instead of fixing it.

**Fix:** Automated script that:
1. Removed all 15 stale alignment pads (with their ponytail comments)  
2. Iteratively found the first misaligned u16, inserted a 1-byte pad right before it, and repeated until all u16s were aligned  

12 pads were inserted (one pad can fix consecutive u16s via the flip in cursor parity). Every existing `*Pad`/`*_Align` symbol is now positioned immediately before the u16 it aligns.

## Files touched
- `asm/ram_map_ewram.s` — removed 15 stale `Pad` symbols, inserted 12 correct `_Align` pad symbols
- `src_custom/card_color_hooks.c` — fixed `INCBIN` → `INCBIN_U16` (agbcc has no 8-bit INCBIN), added cast to `const unsigned char*`
