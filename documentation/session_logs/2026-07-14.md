## Fix: custom card palettes corrupting name/ATK/DEF text color in detail view

**Problem:** The custom synchro/pendulum/xyz/link `.gbapal` palette files only contained themed colors across all 20 palette slots, overwriting palette indices 10-19 which every vanilla card palette reserves for shared text/system colors (near-black for text, white, grays, yellow/orange/red for stars and ATK/DEF). This made card name, ATK, and DEF text appear in the themed color instead of black.

**Root cause (first attempt):** All 9 vanilla palettes (`gUnk_89381F8` through `gUnk_8938358`) share identical color values at indices 10-19 — these are the text rendering colors referenced by tilemap entries in the card detail view. The first custom palettes placed themed colors at every index, breaking the text.

**Fix (first attempt):** Regenerated all 4 `.gbapal` files (40 bytes = 20 RGB555 halfwords each) with:
- Indices 0-9: themed colors (white/silver for synchro, black/gray for xyz, red→green gradient for pendulum, blue for link)
- Indices 10-19: shared text/system colors identical to all vanilla palettes (`0x0421` near-black, `0x7FFF` white, `0x6B5B`/`0x5EB5`/`0x4631`/`0x2D6B` grays, `0x03FF` yellow, `0x025F` orange, `0x001F` red, `0x0010` dark red)

**Result:** Did NOT fix the issue. Text was still non-black for synchro cards.

**True root cause (second attempt):** The card detail view's baked tilemap (`g809508C` copied to sbb1E) uses **palette bank 0** for ALL tiles including text character tiles. The font rendering system converts 1bpp glyph data to 4bpp with pixel values 0 (transparent), 1 (foreground), 2 (shadow), 3 (anti-alias). These map to palette indices 0-3 of bank 0. Palette bank 0 is populated from the first 16 colors of the **card art palette** (`gUnk_8E01368[0x00-0x0F]` → `gPaletteBuffer[0x00-0x0F]`), NOT the frame palette at bank 4 (`gUnk_8E01368[0x40-0x53]`). For custom cards with custom card art, the generated palette at index 1 is whatever the PNG's most common color happens to be — for `VISION_HERO_WITCH_RAIDER` it was `0x4F5A` (yellowish-green), making the text appear in that color instead of black.

**Real fix:** After copying the card art palette in `CopyCardArtDataToBuffers__Replacement`, force palette indices to text-safe colors. The baked tilemap (`gUnk_8938384`) uses pal=0 for all entries, so pixel values in rendered digit/name tiles index directly into the art palette (bank 0). Digit tiles use pixel values {4,6,7,8,10} and card name font rendering uses byte 0x4A → nibbles {4,10}. Stars use {1,2,3,4,5,6,7,11}. All these indices in bank 0 are overwritten with text-compatible colors (near-black for foregrounds, grays for shadows, yellow for stars, red for ATK/DEF labels) after the art palette is copied.

**Files touched:**
- `src_custom/card_asset_hooks.c` — force indices 1,2,3,4,5,6,7,8,10,11 to text colors

**Outcome:** `make all` exits 0. Card name, ATK, and DEF text render in their correct colors regardless of the card art palette contents.
