## Build fixes (second pass — no ROM layout change)

**Worked on:** Fixed `make` errors without altering linker script ROM layout. Initial fix added `src_custom/trunk_hooks.o(.rodata)` to `ldscript.ld` which moved the `.data` section's LMA by 56 bytes, corrupting early-boot initialised-data copy and breaking title screen loading.

**Root cause of regression:** The linker script's `.rodata` entries sit inside the `.text` output section. Inserting a new input section shifts the end-of-`.text`, which shifts all subsequent section LMAs (`.data`, `.bss`, etc.). The GBA boot copies `.data` initial values from ROM to RAM at fixed VMAs — a shifted LMA means it reads from the wrong ROM offset.

**Previous approach (reverted):**
- `ldscript.ld` — added `src_custom/trunk_hooks.o(.rodata)` → reverted
- `src_custom/trunk_hooks.c` — added `const u8 labels[]` → reverted

**New approach:** Initialise the 2-byte `labels[]` array on the stack via explicit assignments instead of a `const` initialiser. This forces agbcc to keep it on the stack rather than placing it in `.rodata`. The `.text` section no longer references `.rodata`, so the linker discards `trunk_hooks.o(.rodata)` (containing only compile-time `lyn_exists_check_*` pointers) without complaint.

### Files

- `src_custom/trunk_hooks.c` — `ExtraDeckViewer_Open`: replaced `const u8 labels[]={...}` with stack-allocated `u8 labels[2]` + per-element assignments
- `ldscript.ld` — reverted `src_custom/trunk_hooks.o(.rodata)` addition

### Outcome

`make` completes successfully. ROM layout unchanged from pre-fix baseline. Game should boot normally.

## Post-sub-menu display refresh fix

**Worked on:** Fixed 3 issues: (1) Extra deck not displaying after "Show in E. Deck", (2) Trunk quantity not decreasing after "Move to E. Deck", (3) Extra deck quantity not increasing. Root cause: sub-menu custom actions exited the sub-menu without triggering a full trunk display refresh, so VRAM/tilemap retained stale data.

### Files

- `src_custom/trunk_hooks.c` — `Trunk_A_Submenu__Replacement`:
  - After sub-menu loop exits due to a custom action (`actionExited`), call full display refresh: `sub_8009364()` + `sub_800A3D8(2)` + `sub_800ABD0()` + `sub_800AA58(6)`
  - Using `sub_800A3D8(2)` (full render: card list header, card grid via `sub_8009A94`, info panel via `sub_800A478`, sort indicator via `sub_800A380`, OAM via `sub_800A5F0(1)`) instead of `sub_800A3D8(3)` (partial render designed for sub-menu context)

### Analysis

- `gCardInfo.id` at offset 0x10 IS the card ID (quantity is fetched separately via `GetTrunkCardQuantity(gCardInfo.id)` at rendering time — card.c line 2706)
- Both `GetTrunkCardQty__Replacement` and `GetTrunkCardQuantity__Replacement` correctly return the updated value from `gTrunkCardQty[]`
- The vanilla display chain for the trunk works correctly — the issue was that our custom action exited the sub-menu without calling the full refresh chain
- `sub_800A3D8(2)` is the correct refresh target (it's what `InitTrunkMenu` uses), NOT `sub_800A3D8(3)` (which is for in-sub-menu partial refresh)

## Extra deck view: direct A-action and display filtering fix

**Worked on:** Fixed two bugs in the extra deck viewing mode.

**Bug 1 — Sub-menu shown on A press in extra deck view:** When viewing the extra deck, pressing A opened the vanilla sub-menu (Details, Move to Deck, Return to Trunk) instead of directly returning the card to the trunk. The user had to navigate to "Move to Deck" to get the correct action.

**Fix:** `Trunk_A_Submenu__Replacement` now checks `gTrunkExtraDeckViewActive` at the very top. When active, it directly removes the card from the extra deck, increments trunk qty, syncs ownership, wraps the cursor, and does a full display refresh (`sub_8009364` + `sub_800A3D8(2)` + refresh chain). The sub-menu is never shown.

**Bug 2 — Extra deck cards wrapping in display:** Vanilla `sub_8009364` renders 12 visible card slots by calling `GetNthCardOnScreen` for each. In extra deck view (e.g. 3 cards), `GetNthCardOnScreen__Replacement` wrapped around, showing the first extra deck card again in later slots. The display showed phantom duplicates.

**Fix:** `GetNthCardOnScreen__Replacement` now returns `CARD_NONE` for out-of-bounds positions when `gTrunkExtraDeckViewActive` is TRUE, instead of wrapping. The display renders only actual extra deck cards with empty slots for the rest.

### Files

- `src_custom/trunk_hooks.c`:
  - `Trunk_A_Submenu__Replacement` — early return with direct remove-from-extra-deck action when in extra deck view
  - `GetNthCardOnScreen__Replacement` — no wrapping in extra deck view, CARD_NONE for out-of-bounds positions

### Outcome

ROM builds cleanly (`make test` passes, only pre-existing failures). In extra deck view:
- A press directly returns card to trunk (no sub-menu)
- Display shows only extra deck cards, no phantom duplicates
- After returning a card, the display refreshes fully
