## Build fixes (second pass — no ROM layout change)

**Worked on:** Fixed `make` errors without altering linker script ROM layout. Initial fix added `src_custom/trunk_hooks.o(.rodata)` to `ldscript.ld` which moved the `.data` section's LMA by 56 bytes, corrupting early-boot initialised-data copy and breaking title screen loading.

**Root cause of regression:** The linker script's `.rodata` entries sit inside the `.text` output section. Inserting a new input section shifts the end-of-`.text`, which shifts all subsequent section LMAs (`.data`, `.bss`, etc.). The GBA boot copies `.data` initial values from ROM to RAM at fixed VMAs — a shifted LMA means it reads from the wrong ROM offset.

**Previous approach (reverted):**
- `ldscript.ld` — added `src_custom/trunk_hooks.o(.rodata)` → reverted
- `src_custom/trunk_hooks.c` — added `const u8 labels[]` → reverted

**New approach:** Initialise the 2-byte `labels[]` array on the stack via explicit assignments instead of a `const` initialiser. This forces agbcc to keep it on the stack rather than placing it in `.rodata`. The `.text` section no longer references `.rodata`, so the linker discards `trunk_hooks.o(.rodata)` (containing only compile-time `lyn_exists_check_*` pointers) without complaint.

### Files

- `src_custom/trunk_hooks.c` — `ExtraDeckViewer_Open`: replaced `const u8 labels[]={...}` with stack-allocated `u8 labels[2]` + per-element assignments
- `ldscript.ld` — reverted `src_custom/trunk_hooks.o(.rodata)` addition

### Outcome

`make` completes successfully. ROM layout unchanged from pre-fix baseline. Game should boot normally.
