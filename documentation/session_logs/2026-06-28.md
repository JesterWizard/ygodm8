## 2026-06-28 — Fixed Pet Baby Dragon game lock on destroy activation

**Files:**
- `src_custom/activated_effects/harpies_pet_baby_dragon.c`

**Bug:** `ResolveTarget` duplicated cleanup that `Duel_HandlePickZoneA` does after the resolver (`UpdateDuelGfxExceptField`, `CheckWinConditionExodia`, `TryActivatingPermanentEffects`). Calling `TryActivatingPermanentEffects` while cursor state was still `DUEL_CURSOR_PICK_ZONE` corrupted state and locked the game.

**Fix:** `ResolveTarget` now only calls `Duel_DestroyZone(zone, INACTIVE_DUELIST, TRUE)` — lets PickZone handler manage cleanup. Also fixed `ACTIVE_DUELIST` → `INACTIVE_DUELIST` for opponent-target GY.

**Outcome:** `make test-cards-build` passes. Destroy effect no longer locks the game.

## 2026-06-28 — Fixed Pet Baby Dragon stat/name corruption and destroy freeze

**Files:**
- `src_custom/permanent_effects/harpies_pet_baby_dragon_stat.c`
- `src_custom/activated_effects/harpies_pet_baby_dragon.c`
- `include/harpies_pet_baby_dragon.h` (new)
- `src_custom/code_8043EF4_hooks.c`

**Stat bug root cause:** `CountHarpieArchetypeOnFixedRowExcluding` calls `Duel_CardNameContains`, which internally calls `SetCardInfo` for each Harpie checked. After counting, `gCardInfo` held the **last** Harpie's stats/name (often Harpie Lady 3). The doubler then ran on those stale values → HL3 name with 2600/2800 instead of PBD 2400/1200.

**Fix:** Call `SetCardInfo(zone->id)` immediately before doubling in `HarpiesPetBabyDragon_ApplyDynamicZoneStats`.

**Destroy freeze fix:** Replaced generic `PickZone` targeting (only card using it) with dedicated cursor state `DUEL_CURSOR_HARPIES_PET_BABY_DRAGON_TARGET` following Invader/Caius pattern. Wired A/B handlers in `code_8043EF4_hooks.c`.

**Outcome:** `make test-cards-build` passes.
