### Final fix: 8bpp + game-accurate palette assembly

**The palette bug:** The raw 256-color palette at the pointer has the map's own bank 0 as entries 0-15 (dark colors). But in 8bpp mode, the GBA BG palette is assembled differently: **font palette (16 colors)** occupies indices 0-15, and **map palette (240 colors)** occupies indices 16-255. The game code (`sub_804F5D8`) does exactly this:
```c
CpuCopy16(g82ADC8C, gPaletteBuffer, 0x20);              // font → indices 0-15
CpuCopy16(g8E11CD0[id], gPaletteBuffer + 0x10, 0x1E0);  // map → indices 16-255
```

Note `+ 0x10` is pointer arithmetic on `u16*`, so byte offset 0x20 = u16 index 16.

Reading all 256 colors from the pointer and using them directly was **off by 16** — pixel value 17 would index `raw[17]` (map color 17), but it should index `combined[17]` which is `map[1]` (map color 1). The map palette's first 16 colors (bank 0 from the pointer data) are never used by the hardware for overworld tiles.

Now: `build_bg_palette()` assembles `font[0..15] + map[0..239]` at indices 0-255. Every pixel value in tile data is ≥16 (confirmed: 0% of tile pixels use the font range), so font palette is present but never referenced by map tiles.

### Map palette gamma correction (final pass)

The sRGB gamma correction was over-brightening extracted images. GBA LCD has lower gamma than modern sRGB monitors. After testing gamma values 1.0, 1.2, 1.3, 1.4, 1.5, 1.8, 2.2:

- Gamma 2.2 (full sRGB): avg brightness ~628 — too bright, washed out
- Gamma 1.4: avg brightness ~576 — better, slightly bright
- Gamma 1.1 (user's choice): user reported "looks great"

Updated `GAMMA = 1.1` in `extract_maps.py` and re-extracted all 61 maps.

### Manifest-driven map graphics overrides

Added `enable_manifest_map_overrides` to `RuntimeConfig`. When TRUE, the game checks `custom_map_manifest.json` entries for vanilla maps (0-60) and redirects graphics loading to a different source map if the entry's `ground` PNG points to a different map.

**How it works:**
1. At build time, `build_custom_maps.py` reads each manifest entry's `ground` field (e.g. `map_09_ground.png` → source map 0) and generates `src_custom/generated/maps/manifest_map_sources.inc` — a `u16[61]` array mapping each map ID to its graphics source.
2. At runtime, `OverworldLoadGraphics__Replacement` checks `gRuntimeConfig.enable_manifest_map_overrides`. If set and `sManifestMapSources[id] != id`, it temporarily sets `gOverworld.map.id` to the source map before calling `CopyOverworldBgGraphics`, then restores the original ID.
3. The override is gated — default `FALSE`. Set `TRUE` in `runtime.c` to enable.

**User workflow:** change the `ground`/`roof` PNG paths in `tools/custom_map_manifest.json` to point to different extracted maps. Rebuild. The game's location will now show the different map's graphics while keeping the original's NPCs, scripts, collision, and music.

### Manifest structure: images grouping + collision overrides

**Images grouping:** Restructured each manifest entry — ground/roof PNG paths are now nested under `images`:
```json
"images": { "ground": "map_09_ground.png", "roof": "map_09_roof.png" }
```

**Collision overrides:** Each entry can optionally specify custom collision via rectangle-based blocking:
```json
"collision": { "blocked": [[0,0,120,1], [0,79,120,1]] }
```
Each rect is `[x, y, width, height]` in 120×80 collision grid coordinates. At build time these are rasterized into `u16[9600]` arrays. At runtime, `sManifestCollisionOverrides[61]` — a pointer table (NULL = use ROM default) — is checked in `OverworldLoadGraphics__Replacement`. When non-NULL and `enable_manifest_map_overrides` is TRUE, `gOverworld.unk23C` is redirected to the custom collision data.

Created `tools/regenerate_manifest.py` — standalone script to regenerate the base manifest from ROM data (preserves existing structure, run after re-extracting map PNGs).
