## Fixed: Custom title screen save-dialog text white without background artifacts (take 8 — font pixel remapping)

**Worked on:**
- Swapping palette[255] at VBlank time made text white but also turned background pixels that use index 255 pure white ("white pixels flooding").
- **Root cause:** the custom palette at index 255 = 0x0000 (black). The background art uses this index. Swapping to white affected those pixels.
- **Final fix:** instead of changing palettes at VBlank time, post-process the font tile data in the EWRAM buffer after dialog setup. The font renders with pixel value 0xFF (palette index 255). `RemapDialogFontPixels()` scans the buffer (gVr + 0xC000, 16KB) and replaces every 0xFF byte with 0x17 (palette index 23). Index 23 is already 0x7FFF (pure white) in the custom palette. No palette swapping needed at VBlank time — the background uses index 23 for its own white pixels, matching the text.
- VBlank callbacks now only touch blend registers (no palette operations).

**Files:**
- `src_custom/title_screen_hooks.c` — added `RemapDialogFontPixels()` function called from `CustomCopyBgGfx()`; removed palette[255] swap from both VBlank callbacks.

**Outcome:** `make all` passes (exit 0). Dialog text uses palette index 23 (already white in custom palette). Background pixels using index 255 are unaffected. No palette changes during dialog open/close.

## Fix: duel icon disappearing during dialogue — 12:13 PM

**Worked on:** Fixed the duel icon disappearing from OBJ tile space when text box / portrait display opens during dialogue.

**Root cause:** Two concurrent issues:
1. OBJ palette slot 14 was overwritten by the portrait system (writes to gPaletteBuffer banks 12-15 via DisplayPortrait in script.c:81), then LoadPalettes() in `sub_804F218__Replacement` and `sub_804EC64__Replacement` copied the corrupted palette to hardware, making the icon's palette data invisible.
2. LoadObjVRAM() in those same functions copies the full charblock 5 (0x06014000-0x06017FFF) to VRAM, overwriting the fire icon tile at 0x3FF * 32 = 0x06017FE0.

**Files touched:**
- src_custom/overworld_hooks.c — changed `DUEL_ICON_PALETTE_NUM` from 14 to 11 (outside portrait's bank 12-15 range); removed `static` from `LoadDuelIconGfx()` so it can be called from other compilation units.
- src_custom/debug/overworld_debug_overlay_hooks.c — added extern declaration for `LoadDuelIconGfx()`; called it after `LoadPalettes()` in both `sub_804F218__Replacement` and `sub_804EC64__Replacement`, guarded by `gRuntimeConfig.enable_repeatable_duel_icon`.

**Outcome:** `make -j$(nproc) all` builds and links successfully. The duel icon now reloads its tile data (at OBJ VRAM 0x06017FE0) and palette (OBJ palette bank 11) after each dialogue frame's LoadObjVRAM + LoadPalettes wipe, keeping it visible during text boxes and portrait display.
