## Soul Taker — crash on activation (PickZone re-entry + state + popup)

**Worked on:** Fixed crash when activating Soul Taker with a valid target.

**Fix 1 (re-entry loop):** `ResolveTarget()` called `ActivateSpellEffect()`, re-entering the dispatch → infinite loop. Changed to call `SoulTaker_ResolveBody()` directly.

**Fix 2 (PICK_ZONE state crash):** After resolve, `gDuelCursor.state` was still `DUEL_CURSOR_PICK_ZONE` (200). In `HandlePlayerBackrowAction__Replacement`, `UpdateDuelGfxExceptField()` ran with this invalid state, crashing the vanilla graphics code. Fixed by (a) `gDuelCursor.state = 0` in `ResolveTarget()`, and (b) reordering the SPELL_TYPE_NORMAL case to handle PICK_ZONE input loop *before* `UpdateDuelGfxExceptField()`.

**Fix 3 (activation gate):** Added `CanActivateSoulTaker()`, auto-detected by the spell dispatch generator, preventing activation when opponent has no monster targets.

**Fix 4 (popup text):** Added `Duel_ShowEffectTextTyped(SOUL_TAKER, 1)` in `EffectSoulTaker()` before targeting, so the activation text appears before the player picks a target.

**Also:** Swapped order in `Duel_ResolveBurnSpell` — `Duel_ShowEffectText` now fires before `Duel_DestroyZone`. Affects Sparks, Hinotama, Ookazi, Tremendous Fire, Meteor of Destruction.
